CSOS

S 应用程序需要同时使用 CPU、内存、磁盘、网络等硬件资源，但硬件接口复杂、资源有限，而且多个程序可能互相干扰。

C 如果每个程序都直接控制硬件，就必须自行处理并发、隔离、故障和设备差异；不同程序还可能覆盖彼此的内存或长期占用 CPU。

Q 操作系统在应用程序与硬件之间解决了什么问题？

A 操作系统通过抽象、隔离和调度，把硬件包装成进程、虚拟地址空间、文件、套接字等稳定接口，并在内核中统一管理和保护共享资源。

1. 核心模型

操作系统的职责可以归为三类：

  1. 抽象：把设备和资源表示成更容易使用的对象，例如进程、文件和虚拟内存。
  2. 复用：让多个任务按时间或空间共享 CPU、内存和 I/O 设备。
  3. 隔离与保护：用用户态/内核态、独立地址空间和权限检查限制故障范围。

2. 用户态与内核态

普通应用运行在用户态，不能直接执行特权指令或任意访问设备。需要内核服务时，应用通过系统调用进入内核；内核验证参数、执行操作，再返回用户态。

系统调用不是普通函数调用：它涉及特权级切换，但不必然引发进程切换。异常和外部中断也可以让 CPU 进入内核：

  • 异常（exception）：由当前指令触发，例如缺页或除零。
  • 中断（interrupt）：通常来自处理器外部，例如网卡或定时器。
  • 系统调用（system call）：应用主动请求内核服务。

POSIX 规定了一组可移植的操作系统接口；C 标准库或系统库通常在其上提供更方便的封装，但并非每个库函数都对应一次系统调用。

3. 内核管理的资源

资源 对应用暴露的主要抽象 内核的主要责任
CPU 进程、线程 调度、抢占、上下文切换
内存 虚拟地址空间、映射 地址转换、页分配、换页、权限保护
存储 文件、目录、文件描述符 VFS、缓存、持久化、权限
网络与设备 套接字、文件描述符 协议栈、驱动、中断、异步事件

4. Linux 系统组成

一套 Linux 系统不只有内核，通常还包括 bootloader、init system、daemon、shell、系统库和应用程序。简化的启动路径是：

  1. 固件初始化硬件并选择启动设备。
  2. bootloader 加载内核及初始文件系统。
  3. 内核初始化内存、调度器和设备，挂载根文件系统。
  4. 内核启动 PID 1；init system 再启动系统服务和用户环境。

内核内部通过虚拟文件系统（VFS）统一不同文件系统的 open、read、write 等操作。Linux 进一步把设备、管道和套接字也纳入文件描述符接口，使许多 I/O 对象可以使用相似的调用方式。

5. 子主题与相邻层次

  • 进程、线程与调度：执行单元、上下文切换、调度和 IPC。
  • syscall：用户态请求内核服务的受控边界。
  • 虚拟内存：地址空间、页表、缺页、映射与写时复制。
  • I/O model：阻塞、非阻塞、readiness 与 completion。
  • 垃圾回收：用户态运行时如何管理托管堆；它不是操作系统内存管理。
  • x86 汇编基础：寄存器、寻址和控制流；它属于机器接口而非操作系统主题。
  • memory：CPU cache、NUMA 与面向程序员的内存性能知识。
  • linker：目标文件、符号、重定位和动态链接。
  • MESI：多核 CPU 的缓存一致性协议。

6. 阅读主线

理解操作系统时，可以沿一次请求的生命周期串联各模块：线程被调度到 CPU，程序访问虚拟地址，必要时触发缺页；它通过系统调用操作文件描述符，内核和设备交互；任务等待 I/O 时退出运行态，完成后重新进入就绪队列。各模块不是孤立概念，而是在这条执行路径上协作。
