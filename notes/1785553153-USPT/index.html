将 SQL 引擎嵌入应用，通过单个本地文件提供事务型关系数据存储

  • S：应用需要一个零配置、可嵌入、单文件的关系型数据库。
  • C：既要完整的 SQL 与事务能力，又不想部署和维护独立的数据库服务。
  • Q：如何在单机环境中低成本地持久化、查询并可靠更新结构化数据？
  • A：SQLite 将数据库引擎直接嵌入应用，通过普通文件提供 SQL、事务和并发控制。

心智模型

SQLite 是一个读写本地数据库文件的嵌入式 SQL 引擎，而不是通过网络访问的数据库服务器。

核心抽象

VFS（Virtual File System）

https://sqlite.org/vfs.html

VFS（Virtual File System）是 SQLite 对操作系统能力的抽象层，使数据库核心无需直接依赖 POSIX、Windows 等平台接口。

它主要负责：

  • 打开、读取、写入、同步和删除数据库文件；
  • 提供文件锁，实现多连接并发控制；
  • 获取时间、随机数以及加载动态库等系统能力。

VFS 由 sqlite3_vfs 表示，打开的文件由 sqlite3_file 表示，其具体 I/O 操作定义在 sqlite3_io_methods 中。 SQLite 通常使用平台默认 VFS，也可以通过连接参数选择或注册自定义 VFS，例如实现内存存储、加密、故障注入或特殊存储后端。

因此，VFS 并不是 SQL 层的虚拟文件系统，而是 SQLite 数据库引擎与底层操作系统之间的适配接口。

状态高度封装

SQLite 的主要持久状态基本就是：database file + WAL file + 少量元数据

把一个 SQLite 实例看成一个可以启动、恢复、迁移的状态胶囊很自然。 SQLite 实例 ≈ 执行引擎 + 一组数据库页 + WAL

便于：

  1. 从远端加载数据库快照；
  2. 在本地执行；
  3. 产生增量变更；
  4. 将增量或新快照上传远端；
  5. 释放计算资源。

单写者模型简化了控制面

同一时刻，一个数据库只有一个拥有写权限的计算节点。

SQLite 非常适合细粒度、单活、serverless 式的计算存储分离；不太适合多个无状态计算节点共享同一个数据库并发写入的计算存储分离。

几种架构

  1. 备份型：SQLite 本地运行，定期把 WAL / 快照上传 S3
  2. 持久化分离型：
  • SQLite 本地运行,事务提交必须持久化到远端日志,本地磁盘只是缓存
  • 远端对象存储或日志服务才是系统真相。
  • 节点丢失后可以：快照 + 日志 → 恢复 SQLite
  1. 页面服务型 SQLite 执行层 ↓ 远程 page server / distributed VFS ↓ object storage
