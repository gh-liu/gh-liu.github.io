进程、线程与调度

2026-08-072026-08-075 出链5 引用
CSOS

S 一台机器上的可运行任务通常多于 CPU 核数，任务还会因为 I/O、锁或定时器反复进入等待状态。

C 系统既要让任务共享 CPU，又要保证交互延迟、公平性、吞吐量和优先级；切换过于频繁还会消耗 CPU 并破坏缓存局部性。

Q 操作系统如何表示执行任务，并决定哪个任务何时运行？

A 进程承载地址空间和操作系统资源，线程承载执行上下文；调度器维护可运行任务并按调度策略把线程分配给 CPU，必要时通过抢占和上下文切换重新分配处理器时间。

1. 进程与线程

  • 进程是资源与隔离的容器，通常拥有独立虚拟地址空间、文件描述符表、信号状态和安全凭据。
  • 线程是内核调度的执行流，拥有程序计数器、寄存器和栈；同一进程内的线程共享地址空间和大部分进程资源。
  • 协程通常由用户态运行时调度，不必与内核线程一一对应；是否并行最终仍取决于承载它的内核线程和 CPU。

Linux 用 task_struct 表示可调度任务，进程和线程都使用这一表示。所谓“进程调度”在现代系统中通常实际调度的是线程。

进程的典型状态包括：

  • running：正在 CPU 上执行。
  • runnable/ready：可以执行，正在运行队列中等待 CPU。
  • sleeping/blocked：等待 I/O、锁、信号或定时器等事件。
  • stopped：被显式暂停。
  • zombie：已经退出，但父进程尚未回收退出状态。

2. 创建与终止

Unix 常把“复制当前进程”和“加载新程序”拆成两步：

  • fork() 创建子进程。父子进程拥有逻辑上独立的地址空间，但内核通常通过写时复制延迟真正复制物理页。
  • execve() 用新程序替换当前进程映像，不创建新的 PID。
  • wait() / waitpid() 让父进程取得子进程退出状态并回收其僵尸记录。
  • _exit() 终止进程。

fork() 后继承的文件描述符引用相同的内核打开文件对象，因此可能共享文件偏移；这与父子进程拥有独立用户态内存并不矛盾。

3. 调度器解决的问题

调度器的输入是任务状态、优先级、运行时间、CPU 亲和性等信息，输出是“哪个可运行线程在哪个 CPU 上执行”。它需要权衡：

  • 吞吐量：单位时间完成更多工作。
  • 响应时间：交互任务尽快得到 CPU。
  • 公平性：避免普通任务长期饥饿。
  • 实时约束：高优先级实时任务满足时限。
  • 局部性：尽量复用热 cache，减少跨 CPU 迁移。

抢占式与协作式

  • 抢占式调度：调度器可以挂起正在执行的任务，把 CPU 交给另一个任务。通用操作系统主要依靠这种方式保证响应性和隔离。
  • 协作式调度：任务主动让出执行权。切换点更可控，但一个不让出的任务会阻塞其他任务。

二者可以组合：内核线程由操作系统抢占，语言运行时中的协程既可以在阻塞点协作让出，也可以由运行时机制抢占。

多核负载均衡

多核系统通常为每个 CPU 维护运行队列，避免所有 CPU 竞争一个全局队列。任务可以通过以下方式重新分布：

  • 工作分享（work sharing）：主动把任务推送到较空闲的执行器。
  • 工作窃取（work stealing）：空闲执行器从繁忙执行器获取任务。

平衡负载会改善利用率，但任务迁移会损失缓存和 NUMA 局部性，因此不是越频繁越好。

Linux 调度策略

Linux 同时提供普通分时和实时调度类：

  • 普通任务由公平调度类管理；Linux 历史上经历了 O(n)、O(1)、CFS 等实现演进，具体实现会继续变化。
  • SCHED_FIFO 和 SCHED_RR 面向固定优先级实时任务。
  • 调度类先决定哪类任务优先，再由类内部策略选择具体任务。

理解原则比记住某一版内核的数据结构更重要：调度器必须快速选择任务，同时维护公平性、优先级和多核负载。

4. 上下文切换

上下文切换保存当前线程的寄存器、程序计数器和栈指针，并恢复另一个线程的状态。切换成本不只有保存寄存器，还可能包括：

  • 调度器执行时间。
  • cache、TLB 和分支预测器中的热状态丢失。
  • 地址空间切换带来的页表上下文变化。

系统调用只表示从用户态进入内核态；如果调用可以立即完成，原线程可直接返回，不必切换到另一个线程。只有阻塞、抢占或调度决策等情况才需要任务切换，详见 syscall。

5. 进程间通信（IPC）

机制 数据模型 典型特点
signal 小型异步通知 信息量有限，处理时机受信号语义约束
pipe / FIFO 字节流 适合单机流式通信；FIFO 有文件系统名称
message queue 有边界的消息 保留消息边界，由内核托管
shared memory 共享字节区域 少复制、吞吐高，但必须另行同步
socket 字节流或数据报 同机和跨机器均可使用

共享内存只解决“双方能看到同一块数据”，不解决并发读写的顺序和原子性；通常还需要 mutex、semaphore、futex 或原子操作。
