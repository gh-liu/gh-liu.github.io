面向 SSD 的嵌入式 LSM-tree KV 存储引擎

  • S：应用需要在单机上持久化大量有序 KV，并以高吞吐写入、点查或范围扫描访问。
  • C：原地随机写放大 I/O；纯内存写虽快，却无法抵御进程崩溃。
  • Q：如何把随机更新转化为顺序写，同时兼顾持久性与可接受的读取成本？
  • A：RocksDB 将 WAL、MemTable、不可变 SST 和后台 Compaction 组成 LSM-tree，以写放大换取高写入吞吐。

心智模型

RocksDB 本身不是数据库，它为什么能够成为 TiDB、CockroachDB、Yugabyte、MyRocks 等数据库的底层？ RocksDB 提供了一套 MVCC + Snapshot + Transaction API。

RocksDB 是嵌入应用进程的有序 KV 存储引擎，不是独立数据库服务。

  • key/value 都是字节串，key 按 comparator 排序；支持 Put、Get、Delete、Merge、批量写和范围迭代。
  • 没有内建网络协议、SQL、复制、分片或分布式事务，这些由上层系统实现。
  • 从 LevelDB 演化而来，针对多核与 SSD 优化；核心数据结构见 LSM-tree。

核心抽象

读写链路

  • WAL：追加记录写操作，崩溃后重放未 flush 的 MemTable；持久性取决于 WriteOptions.sync 等配置。通用原理见 WAL。
  • MemTable：默认使用并发 SkipList 保存有序数据；满后冻结，由后台线程 flush。
  • SST：不可变、有序、分块且可压缩；索引定位 data block，Bloom Filter 跳过确定不存在的文件。
  • Compaction：合并 SST、清理旧版本与 tombstone，以额外后台写入降低读放大和空间放大。默认是 Leveled Compaction：L0 文件范围可重叠，L1 及以下同层不重叠。
  • Block Cache：缓存解压后的常用 data/index/filter block，通常是读性能的关键内存预算。
  • Column Family：同一 DB 内共享 WAL、独立维护 MemTable/SST 与配置的逻辑 KV 空间；不是事务或资源完全隔离的独立数据库。

三种放大

指标 含义 主要改善手段
读放大 一次逻辑读检查的内存表、文件或 block 数 Bloom Filter、缓存、及时 compaction
写放大 用户写入触发的 WAL、flush、compaction 总写入量 compaction 策略、层级大小、批量写
空间放大 物理占用 / 有效数据量 compaction、清理 tombstone/旧版本

调优本质是在三者与内存、CPU、尾延迟之间取舍，不存在通用最优配置，应以真实 workload benchmark。

MVCC 与快照

RocksDB 的 internal key 可简化为：

  • 每次写入分配单调递增的 sequence number，更新和删除都产生新版本而非原地修改。
  • 一次读捕获当前 published sequence，只读取不大于它的最新版本；Snapshot 固定该序号供多次读复用。
  • 活跃 snapshot 会阻止 compaction 删除其仍可能读取的旧版本，因此必须及时释放。
  • WriteBatch 中的多条修改一起发布，对其他读者原子可见；但它不提供条件判断或完整事务隔离。

事务

事务写入先暂存在 transaction buffer，commit 时原子写入 RocksDB；事务可读到自己的未提交写入。

模式 冲突检查 适用场景
TransactionDB 写入时获取 key lock，冲突时等待或超时；可能死锁 冲突多、重试成本高
OptimisticTransactionDB 写入不加 key lock，commit 时校验；冲突则整笔重试 冲突少、事务短且重试便宜

注意：

  • snapshot read 提供一致视图，但仅检测 write-write conflict 仍可能出现 write skew。
  • 依赖读取结果做更新时使用 GetForUpdate，把读集合纳入冲突检测。
  • 点 key 锁不能阻止范围扫描的 phantom；不要默认等同于 SQL 数据库的 Serializable。
  • RocksDB 原生事务只覆盖单个本地实例；分布式数据库通常在其上实现自己的事务层。

Merge Operator

Merge(key, operand) 不立即执行 read-modify-write，而是记录增量 operand，在读取、flush 或 compaction 时由自定义 Merge Operator 合并。它减少小增量更新的写放大和并发覆盖，但会把尚未合并的计算成本转移到读取路径。
