如何在不修改业务代码的情况下，让并发测试从`不确定`变成`可证明完成`？

testing/synctest 用于确定性测试并发代码，尤其适合测试超时、取消和异步回调。

Go Runtime 是如何证明整个并发系统已经静止（quiescent）的？

Bubble

synctest.Test 在隔离的 bubble 中运行测试；测试内创建的 goroutine 也属于该 bubble：

Bubble 提供两项关键语义：

  • 虚拟时间：初始时间固定为 2000-01-01 00:00:00 UTC；当所有 goroutine 都持久阻塞时，时间自动推进到下一个定时事件，因此测试无需真实等待。
  • 持久阻塞（durably blocked）：goroutine 只能被同一 bubble 内的 goroutine 唤醒，例如等待 bubble 内的 channel、sync.Cond、sync.WaitGroup 或 timer。

边界：Bubble 隔离的是并发语义，不是系统资源。网络 I/O、系统调用以及 sync.Mutex 等可能受外部事件影响，不属于持久阻塞；测试应避免外部进程和真实网络，改用内存实现（如 net.Pipe）。

API

  • synctest.Test(t, f)：运行 f，并在返回前等待 bubble 内所有 goroutine 退出；死锁会使测试失败。
  • synctest.Wait()：等待其余 goroutine 全部进入持久阻塞状态，常用作并发断言前的确定性同步点。
