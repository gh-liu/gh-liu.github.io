Unix fork 的进程复制语义、写时复制、文件描述符继承与多线程陷阱

  • S：Unix 需要创建新进程，并允许新进程在启动另一个程序前调整文件描述符、凭据和执行环境。
  • C：完整复制进程地址空间成本很高；复制正在运行的多线程进程还可能继承不一致的用户态状态。
  • Q：fork() 复制了什么、共享了什么，为什么通常紧接 exec()？
  • A：fork() 创建调用进程的子进程，复制进程语义但通过写时复制延迟内存复制；父子随后独立执行，而文件描述符仍引用相同的内核打开文件对象。子进程通常完成少量设置后调用 exec()。

基本语义

一次成功的 fork() 调用会在父、子进程中各返回一次，从而产生两条执行流：

  • 父进程得到子进程 PID。
  • 子进程得到 0，并从 fork() 返回处继续执行。
  • 失败时父进程得到 -1，不会产生子进程。

父子谁先运行没有保证。依赖调度顺序的程序存在竞态，应使用 pipe、signal、wait 或其他同步机制表达顺序。

复制与共享

地址空间：逻辑复制，物理页暂时共享

父子拥有独立虚拟地址空间。内核通常不立即复制所有可写页，而是把页暂时只读共享；任一方写入时触发缺页，再为写入方复制物理页。这就是 虚拟内存 中的 Copy-on-Write。

COW 让 fork() -> exec() 很便宜，但并非零成本：内核仍需复制页表和进程元数据。大地址空间、频繁缺页或 fork 后大量写入都会增加成本；透明大页也可能放大 COW 开销。

文件描述符：复制 descriptor，共享 open file description

子进程继承文件描述符表的副本，但父子 descriptor 通常指向同一个内核 open file description，因此共享：

  • 当前文件偏移；
  • 文件状态标志，如 O_APPEND；
  • socket、pipe 等内核对象。

关闭一方的 descriptor 不会让另一方自动关闭；内核对象在最后一个引用释放后才销毁。descriptor 自身的 FD_CLOEXEC 标志决定它是否在成功 exec() 时关闭。

其他状态

当前工作目录、环境、信号 mask、资源限制和凭据等会按各自规则继承。pending signal、计时器、锁以及进程统计并非都做简单复制；编写系统代码时应查询目标平台的 fork(2) / POSIX 语义，而不是类推。

fork、exec、wait 的职责

  • fork()：创建进程，保留调整执行环境的窗口。
  • exec*()：用新程序替换当前进程映像，不创建新 PID；成功时不返回。
  • wait*()：父进程获取退出状态并回收僵尸记录。

子进程已退出但父进程尚未 wait 时成为 zombie，只保留 PID 和退出状态等少量信息。长期不回收会耗尽进程表项，详见 进程、线程与调度。

多线程进程中的陷阱

多线程进程调用 fork() 后，子进程只有调用线程存活，其他线程消失；但它们持有的 mutex 可能以“已加锁”状态留在复制的内存中。子进程若再调用 malloc()、日志库或其他可能取锁的函数，可能永久死锁。

因此在 fork() 与 exec() 之间：

  • 只调用 async-signal-safe 函数；
  • 尽量只做 dup2()、close()、execve()、_exit() 等必要操作；
  • 不要刷新继承的 stdio buffer，也不要用 exit() 执行复杂清理；
  • 需要复杂准备时优先考虑 posix_spawn()，由实现选择更安全高效的路径。

pthread_atfork() 可以在 fork 前后修复应用自己控制的锁，但无法可靠修复所有第三方库状态，因此不是通用解法。

常见错误

  1. 重复缓冲输出：fork 前未刷新的用户态 stdio buffer 被复制，父子都 exit() 时可能各输出一次。
  2. 共享文件偏移竞态：父子同时读写同一 open file description，偏移互相影响。
  3. descriptor 泄漏到新程序：创建 descriptor 时未设置 close-on-exec；多线程下优先用支持原子 CLOEXEC 的接口。
  4. exec 失败后继续执行业务代码：子进程应报告错误后 _exit()，不能跌回父进程路径。
  5. 不回收子进程：忽略 wait*() 和 SIGCHLD 生命周期，积累 zombies。
  6. 假设 fork 便宜：大型进程即使不复制数据页，也有页表、内核 bookkeeping 和后续 COW 成本。

替代方式

  • posix_spawn()：表达“创建并立即运行新程序”，对多线程进程通常更安全，也允许平台优化。
  • vfork()：父进程暂停，子进程临时共享地址空间；约束严格，误用会破坏父进程状态，应交给 libc 或成熟封装选择。
  • 长期 worker / prefork：提前创建进程以摊销成本，但必须处理连接、配置和进程监督。
