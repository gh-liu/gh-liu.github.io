CSOS

S 多个进程同时运行，都希望拥有连续、稳定且足够大的内存空间，但物理内存有限且会被动态分配。

C 直接使用物理地址会让程序依赖实际内存布局，进程之间也无法可靠隔离；一次越界写就可能破坏内核或其他进程。

Q 操作系统如何给每个进程提供独立地址空间，同时高效复用物理内存？

A CPU 的 MMU 按操作系统建立的页表，把进程虚拟地址翻译为物理地址；页表项同时记录权限和驻留状态，内核通过缺页处理、按需分配、映射和换页管理物理内存。

1. 为什么需要地址转换

虚拟内存引入一层间接映射，主要解决三个问题：

  1. 隔离：每个进程有独立地址空间，相同虚拟地址可以映射到不同物理页。
  2. 重定位：程序不必知道最终装入哪块物理内存。
  3. 复用：物理页可以按需分配、共享、回收或换出，而虚拟地址布局保持稳定。

虚拟地址空间大于物理内存并不意味着所有地址都可实际使用；可用容量还受页表、交换空间、提交策略和进程限制约束。

2. 分页与地址翻译

内存按固定大小的**页（page）**管理，常见基础页大小是 4 KiB。虚拟地址由虚拟页号和页内偏移组成：

CPU 的 MMU 完成每次地址翻译，操作系统负责创建和修改页表。页表项（PTE）通常包含：

  • 物理页框号。
  • present/valid 状态。
  • 用户态/内核态访问权限。
  • 可读、可写、可执行权限。
  • accessed、dirty 等状态位。

现代 64 位地址空间很大，单级页表会浪费大量内存，因此采用多级页表，仅为实际使用的地址范围分配下级页表。TLB 缓存近期翻译结果，避免每次访存都遍历页表。

“地址高 10 位查页目录、中间 10 位查页表”只适用于经典 32 位 x86 的特定分页模式，不是通用分页模型。

3. 缺页异常

当页表无法完成访问时，CPU 触发缺页异常，由内核判断原因：

  1. 尚未分配物理页：为匿名映射分配并清零物理页，再建立映射。
  2. 文件映射尚未载入：从文件读取对应页。
  3. 页面已换出：从交换区读回。
  4. 写入只读的 COW 页：复制物理页并让当前映射可写。
  5. 非法地址或权限不符：无法修复，Unix 通常向进程发送 SIGSEGV 或 SIGBUS。

因此，申请虚拟地址范围不等于物理内存已立即分配。按需分页把许多成本推迟到第一次实际访问。

4. 进程地址空间

典型用户进程映像包含：

  • 代码和只读数据。
  • 已初始化数据段。
  • BSS（未初始化或零初始化的静态存储）。
  • heap。
  • 线程栈。
  • 共享库。
  • 文件映射和共享内存。

目标文件中的 section 是链接视角的组织单位；装载器按照 segment 把可执行文件区域映射进进程。可用 readelf -S 和 readelf -l 分别查看。

栈帧是函数调用的活动记录，通常包含返回信息、保存的寄存器和局部数据，但具体布局由 ABI 和编译器决定。局部变量也可能被优化到寄存器、消除或移动到其他位置，不能简单等同于“所有局部变量都在栈上”。

5. 内存映射接口

  • brk() 调整传统进程 heap 的边界；现代分配器通常只把它作为一种向内核申请大块内存的方式。
  • mmap() 创建匿名映射或文件映射，可用于 heap、大对象、共享库和共享内存。
  • munmap() 删除一段映射。
  • mprotect() 修改映射权限。

malloc() / free() 通常是用户态分配器接口。分配器通过 brk() 或 mmap() 从内核取得大块地址空间，再用空闲链表、size class、arena 等机制切成小对象；每次 malloc() 不一定产生系统调用。

内核本身也需要物理页分配器。伙伴系统适合管理连续的 2 的幂次页块；slab/slub 类分配器在其上高效管理常用内核对象。它们和用户态 malloc() 是不同层次。

6. 共享与写时复制

不同虚拟地址可以映射同一个物理页：

  • 共享库代码页可以被多个进程共享。
  • 文件映射让文件内容进入页缓存并映射到进程。
  • 共享内存让进程直接读写共同物理页。

fork() 后，父子进程的私有可写页通常暂时共享并标为只读。任一方写入时触发缺页，内核复制该页后分别建立可写映射，这就是写时复制（copy-on-write）。它避免在 fork() 当下复制整个地址空间。

7. 分段与分页

早期 x86 实模式使用“段基址 + 偏移”形成物理地址；保护模式的段描述符还可表达范围、权限和特权级。分页则以固定大小切分地址空间，更便于分配、回收和换页。

现代 64 位通用操作系统主要依赖分页完成隔离和内存管理。在 x86-64 的常见平坦内存模型中，传统代码段和数据段的基址作用大幅弱化；不要把早期 32 位分段机制直接套到现代系统。

8. 性能代价

虚拟内存的主要性能问题包括：

  • TLB miss 导致页表遍历。
  • 缺页需要分配物理页，严重时还涉及磁盘 I/O。
  • 工作集超过物理内存会引发频繁换页（thrashing）。
  • 多核下修改页表后可能需要 TLB shootdown。
  • NUMA 系统中，物理页所在节点影响访问延迟。

大页可以减少 TLB 压力，但会增加内部碎片和分配、回收的复杂度，并非默认越大越好。
